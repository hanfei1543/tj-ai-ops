# Goods Receive AI SOP（来源：目标机 Desktop\operation\Goods_Receive_AI_SOP_V1.txt，V1.0）

Goods Receive AI 自动化工作流程（SOP）
版本：V1.0（根据 2026-11-06 口述整理）
状态：业务规则整理稿；上线前需验证实际软件界面、字段和异常处理。

一、目标
通过扫描供应商 Delivery Order（DO），由 AI 读取资料、识别手写 Item Code、排除退货或损坏商品、获取进货价，在本地 Goods Receive 软件录入有效商品；必要时更新 Item Master，并输出修改报告。

二、DO 读取与入货
1. 员工扫描 DO，扫描件保存至电脑指定文件夹。
2. AI 读取 DO，提取商品资料、手写 Item Code、价格及备注。
3. 标注 Pulang（退回）或 Rosak（损坏）的项目不进入 Goods Receive。
4. DO 上有进货价格时直接读取；没有价格时，到用户所说的 MyTax 网站查询（网站名称、检索方法待现场核实）。
5. 手写 Item Code、金额或备注无法可靠辨识时，交人工核对，禁止猜测。
6. 将符合条件的商品输入本地 Goods Receive 软件。实际界面操作、数量核对、重复 DO 防护及提交步骤仍需实测确认。

三、GOLD HARVEST 成本代号
数字字母映射：G=1，O=2，L=3，D=4，H=5，A=6，R=7，V=8，E=9。
位值标记：T=RM100，S=RM10，Y=RM1，X=RM0.10。数值字母紧接位值标记表示乘法，多个部分相加；没有出现的位视为零。
已确认示例：
OSHY = O×S + H×Y = 2×10 + 5×1 = RM25.00。
LTDSY = L×T + D×S = 3×100 + 4×10 = RM340.00（尾随 Y 代表个位为零的例子，按既有样式保留）。
EY = E×Y = RM9.00。
AX = A×X = RM0.60。
说明：S 在 GOLD HARVEST 字母序列中是第十个字母，但在价格代码中已确认作为十位标记使用；不能把 S 当作普通数字 10 再叠加计算。零位标记的完整标准写法、超过 RM999 和不同组合的格式，尚需实际样本验证。

四、成本比较及变价触发
1. 进入 Item Master，读取该商品现有 Color Code，按上述规则解码为原本底价。
2. 将本次实际进货价与原本底价比较。
3. 若新进货价低于或等于原本底价：Item Master 九个字段全部不修改。商品是否照常完成 Goods Receive，以实际入货规则执行。
4. 若新进货价高于原本底价：执行第五节的九字段更新。

五、涨价时的九字段更新
A. Unit Cost = 最新实际进货价，保留原始精度，不向上进位。
B. Min. Price（Minimum Price）= 最新实际进货价，必须与 Unit Cost 相同。
C. Color Code = 先将最新实际进货价无条件向上进位至 RM0.10，再按 GOLD HARVEST 编码。
D. 六个售价字段分别在原价基础上增加同一笔涨幅：List Price、SP1、SP2、SP3、INV Price 1、INV Price 2。

成本涨幅 = 最新实际进货价 − 原本 Color Code 解码底价。
售价增加额 = 将（成本涨幅 × 1.10）无条件向上进位至 RM0.10。
每个新售价 = 对应字段原售价 + 售价增加额。
注意：只对“售价增加额”进位一次，不是把六个字段原价各自先行进位。

例子：原本 Color Code 底价 RM10.00；实际新进货价 RM12.44。
成本涨幅 = RM2.44；RM2.44 × 1.10 = RM2.684；向上进位至 RM0.10 = RM2.70。
Unit Cost = RM12.44；Min. Price = RM12.44；Color Code 以 RM12.50 编码。
List Price、SP1、SP2、SP3、INV Price 1、INV Price 2 分别在各自原价上加 RM2.70。

向上进位示例：RM12.31→RM12.40；RM12.35→RM12.40；RM12.40→RM12.40；RM12.44→RM12.50；RM12.49→RM12.50。
采用十进制金额运算，避免浮点误差；如果实际系统字段仅接受两位小数，必须验证其存储精度。

六、修改报告
只要实际修改了 Item Master 价格资料，生成报告。至少记录：处理时间、供应商、DO 识别信息、Item Code、原 Color Code、新 Color Code、原底价、新实际进货价、成本涨幅、售价增加额、九个字段的旧值和新值、修改结果（成功／失败／待人工核对）以及错误原因。
报告应区分“计划修改”与“软件已保存且复核成功”，不能仅因 AI 输入了内容就报告成功。无价格修改时可以记录正常入货结果，但不必生成价格变动明细。

七、执行安全要求
1. 识别不清的手写代码、缺失进货价、无法解码的 Color Code、无法找到的 Item、异常金额或软件错误，暂停该项目并人工确认。
2. 修改前保留原值；保存后重新读取验证九个字段。
3. 同一 DO / Item 防重复处理；保留可审计的处理记录。
4. 建议先在测试资料上验证，正式环境初期由人员审批变价操作。

八、仍需现场确认的实施细节
- 指定扫描文件夹、扫描文件格式和命名规则。
- MyTax 网站的准确名称、登录及价格查询步骤。
- Goods Receive 软件的实际录入字段、数量、税费、提交和过账流程。
- GOLD HARVEST 代码的标准输出格式（尤其零位、超过百位及小数组合）。
- 售价字段是否允许出现零或负值，及异常项目处理。
- 报告的最终格式（Excel/PDF/文本）和保存位置。

本 SOP 仅整理已口述确认的业务规则，不代表已完成本地软件自动化测试。
