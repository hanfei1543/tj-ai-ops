# 员工界面中文化 —— 变更说明与旧版→新版对照

> 对应 commit c384a24。中文标签唯一真相源：web/src/lib/core/ui-labels.js（纯逻辑可测试，raw 字段保留原始 code 供技术详情/排障）。
> 原则：状态文案绝不合并 IRS 阶段；错误码/UUID/SHA/版本号/RPC 名保留在底层，只不堆给普通员工。

## 一、四个页面变更说明

### 1. 采购单列表（TjPoSystemPage）
- 新增状态筛选（全部/待处理/发送中/已发送/已合并/待审批/已取消），只按后端真实状态。
- 卡片业务字段优先：采购单编号、供应商、采购日期、业务状态、下一步操作；技术字段（供应商编号/开单人/来源单/内部 UUID）折叠进「技术详情」。
- 移除英文 "Purchase Order"；顶部改为「测试环境：数据不会自动进入 IRS」。

### 2. 新建采购单（TjPoSystemPage 编辑器）
- 补「采购日期 *」必填（type=date，初值来自 DB 或空，不默认当天）。
- 行内显示小计 + 总金额（RM）；保存时显式校验并传 websitePoDate（尾参数）。
- 冻结单据日期输入禁用；缺供应商/缺日期/数量非法 → 字段旁中文提示。

### 3. 收货记录列表（ReceiptListPage）
- 业务字段优先：记录编号、供应商、收货日期、送货单/发票、状态、下一步操作提示。
- 警告码改中文解释（warningLabel），不再只显示「警告 1」；异常改「有 N 项需要确认」。
- 移除技术字段：v/revision、操作人、checked_by、updated_at、英文 "Receipt Event"。

### 4. 收货详情/审批（ReceiptDetailPage）
- 重排为四区：收货资料 / 商品核对（订购 vs 本批实收 vs 差额）/ 需要注意的问题（中文解释 warning/exception）/ 下一步操作。
- 「确认例外（超收/额外行）」仅在确有 exceptions 且后端要求确认时出现，不默认要求勾选。
- 标题「收货详情」；底部「技术详情/审计记录」折叠（receipt_event_id、po_header_id、source_refs、task_id、SHA、revision、服务器错误码、操作人原始 ID）；任务区改「系统处理进度」。

### 5. 门禁（GrAuthGate）
- 角色用 roleLabel（员工/审批人员/执行人员/管理员）+「测试环境」标识；隐藏裸账号名（title 保留原始账号）。
- 顶部提示改「测试环境：数据不会自动进入 IRS。权限由服务器强制，本页按钮只决定显示。」
